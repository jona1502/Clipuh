# Licensing and third-party notices

## clipuh's own license: owner decision required

clipuh has **no project license yet**. There is no `LICENSE` file, no `license` field in any
`Cargo.toml`, and no recorded licensing decision in the repository. The GitHub repository is
private. Without a license, all rights are reserved by the copyright holder(s): nobody else
may copy, modify or redistribute the source code or binaries, beyond what GitHub's terms allow
for viewing a repository they have been given access to.

This is a **release blocker**: before binaries are distributed, the owner has to decide how
clipuh is licensed. Nothing in this repository should be read as choosing a license.

| | Proprietary (closed source) | Open source (e.g. MIT, Apache-2.0, GPL-3.0) |
| --- | --- | --- |
| Source code | Stays private | Published; anyone may read, modify and redistribute under the license terms |
| Binaries | Distributed under an end-user license (EULA) that the owner writes | Distributed under the same license as the source |
| Third-party crates | Allowed: every dependency below permits use in closed-source binaries, given the notices are shipped | Allowed; copyleft licenses (GPL) also bind clipuh's own code |
| Repository visibility | Stays private; public downloads need a separate public release location | Can be made public |
| Contributions | Governed by agreements with each contributor | Governed by the license (optionally a CLA/DCO) |

Once decided, update:

- `LICENSE` (open source: the license text with the real copyright holder) or an EULA file
  (proprietary), at the repository root.
- `workspace.package` in `Cargo.toml`: `license = "<SPDX expression>"` for an open-source
  license, or `license-file = "LICENSE"` for a custom/proprietary license; then
  `license.workspace = true` in each `crates/*/Cargo.toml`. Do not add an SPDX identifier
  before the decision.
- The "License" section of `README.md`.
- The release package: ship the license/EULA next to `clipuh.exe` (see below).
- `about.toml`: if the workspace crates get a license, `private = { ignore = true }` keeps
  them out of the third-party notices either way.

## Third-party Rust crates

[`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) lists every crate compiled into
`clipuh.exe` for `x86_64-pc-windows-msvc`, with the license it is used under and the full
license text (including the copyright notices shipped in each crate). It is generated by
[cargo-about](https://github.com/EmbarkStudios/cargo-about) 0.9.3 from `Cargo.lock`:

- `about.toml`: target, scope (normal dependencies only; build/dev dependencies and the
  workspace's own `publish = false` crates are excluded) and the list of accepted licenses.
- `scripts/licenses/about.hbs`: the Markdown template.
- `scripts/licenses/generate-notices.sh`: regenerates the file; `--check` fails if it is out
  of date. It runs offline from the crates `cargo fetch` downloads, so the output depends only
  on the lockfile, the configuration and the template.

```text
cargo install --locked --features cli cargo-about@0.9.3
scripts/licenses/generate-notices.sh          # after changing dependencies
scripts/licenses/generate-notices.sh --check  # what CI runs
```

The CI job "Licenses" runs the check on every PR. A dependency whose license is missing, not
identifiable, or not in the accepted list fails generation, so new licenses need a deliberate
review and an `about.toml` change.

### Inventory (Cargo.lock at the time of writing)

406 third-party crates. Where a crate offers a choice (`MIT OR Apache-2.0`), the first
accepted license in `about.toml` order is used, normally MIT.

| License used | Crates | Main obligations for binary distribution |
| --- | ---: | --- |
| MIT | 357 | Include copyright notice and license text |
| ISC | 23 | Include copyright notice and permission notice |
| Apache-2.0 | 22 | Include license text; keep NOTICE files (none of the crates ships one) |
| Unicode-3.0 | 20 | Include copyright and permission notice (ICU data crates) |
| BSD-3-Clause | 10 | Include copyright notice, conditions and disclaimer; no endorsement |
| BSD-2-Clause | 5 | Include copyright notice, conditions and disclaimer |
| Zlib | 5 | Keep notices in source; attribution in binaries appreciated, not required |
| MPL-2.0 | 1 | `option-ext` 0.2.0, see below |

Counts add up to more than 406 because some crates are licensed under several licenses at
once (for example `ring`: Apache-2.0 AND ISC).

Notable components: GPUI 0.2.2 and its `gpui_*` crates (Apache-2.0, Zed Industries), the
`windows` crates (MIT, Microsoft), `ring`/`rustls` (TLS stack pulled in by GPUI's HTTP
client), `image` with its codec crates, and ICU4X (Unicode-3.0).

**MPL-2.0 (`option-ext`, via `directories` → `dirs-sys`):** MPL is file-level copyleft. clipuh
uses the crate unmodified, which permits distribution in a closed-source binary as long as
recipients are told where the MPL-covered source is available. `THIRD_PARTY_NOTICES.md`
includes the license and the repository link (<https://github.com/soc/option-ext>); the
source is also published on crates.io. If the crate is ever modified, the modified files must
be made available under MPL-2.0.

### Known gaps

- **18 crates are packaged without a license file:** `convert_case` 0.4.0, `dtor` 0.0.6,
  `dtor-proc-macro` 0.0.5, `lyon` 1.0.19, `lyon_algorithms` 1.0.22, `lyon_geom` 1.0.20,
  `lyon_path` 1.0.19, `lyon_tessellation` 1.0.23, `mac` 0.1.1, `profiling` 1.0.18,
  `profiling-procmacros` 1.0.18, `seahash` 4.1.0, `simd_helpers` 0.1.0, `stacksafe` 0.1.4,
  `stacksafe-macro` 0.1.4, `svg_fmt` 0.4.5, `taffy` 0.9.0, `zune-inflate` 0.2.54. Their
  notices use the standard text of the declared license without the upstream copyright line.
  Fixing this needs `[<crate>.clarify]` entries in `about.toml` pointing at the license files
  in each crate's upstream repository (several are proc-macros that are not part of the
  binary at all).
- The inventory follows Cargo's feature resolution for the whole workspace, so it may list a
  few crates that end up unused in the final binary. Over-listing is harmless.
- **The release package does not ship the notices yet.** The MIT, BSD, ISC and Apache
  licenses require the notices to accompany binary copies. Once the release workflow
  (`scripts/release/package.ps1`, separate PR) is on `main`, add `THIRD_PARTY_NOTICES.md`
  (and the project license/EULA) to its payload next to `clipuh.exe`. An in-app "Licenses"
  view is a possible later addition.

### Not redistributed

clipuh uses these Windows components at run time but does not ship them, so they need no
notice: Media Foundation (H.264/AAC), Direct3D 11/DXGI, Windows Graphics Capture, WASAPI,
WinMM, the Segoe Fluent Icons / Segoe MDL2 Assets fonts (drawn by name, not bundled) and the
GPU vendors' hardware encoder drivers.

The website (`website/`, Astro) is a separate product with its own npm dependencies (for
example `@fontsource-variable/inter`, OFL-1.1). It is not part of the app and is not covered
by `THIRD_PARTY_NOTICES.md`.
